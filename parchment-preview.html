为什么设计系统需要三层 Token

设计系统的核心矛盾是一致性和灵活性的平衡。只有色板层，换主题要改几百个地方；只有语义层，不知道底层色值是什么，调整起来没抓手。

三层 Token 的本质，是在「原始值」和「组件样式」之间，加了一层「用途命名」的缓冲。这一层缓冲，让整个系统既能保持一致，又能灵活变化。

第一层：Palette

纯描述性的色值，就像画家的颜料盒。只说「这个颜色叫 parchment-50」，不说它用来干什么。

第二层：Semantic

按用途命名的角色 token。surface-page、text-primary、border-default。组件引用这一层。

第三层：Component

组件级别的具体规格。如果某个组件需要特殊调整，改这一层，不影响其他组件。

// 改主题色 → 只改 accent-600
// 改深色模式 → 只改 semantic 的 dark 覆盖
// 改按钮颜色 → 只改 button component token

每层只对上一层负责，不会牵一发动全身。

按钮文案

写：保存更改
不写：提交 / 确定
写：删除项目（不可恢复）
不写：是的 / OK

错误文案

不写：密码格式错误
